# Gaussian splat renderer implementation notes

This checkout retains the complete official CIS5650 Fall 2025 Project 5 history, original README in README.upstream.md, source credits and MIT license (copyright 2024 shrekshao). New implementation work is original to this checkout. No student solution or externally licensed scene was imported.

Run `npm ci`, `npm run check`, `npm run build`, then `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5186 --strictPort`. The CPU check uses native TypeScript stripping, verified locally on Node25.8.1. Vite is pinned to 6.4.4, the smallest patched major line used here; npm audit was reduced from six reported vulnerabilities to zero. Lockfile is authoritative. No deploy workflow was enabled.

Use **Load synthetic scene**, then select Gaussian or point cloud. Left drag looks around, right drag pans, and wheel moves. Camera JSON presets remain supported but are no longer required before drawing. Gaussian multiplier adjusts covariance scale. **GPU diagnostics** executes the real Gaussian frame and reads GPU sort/splat buffers into visible JSON; diagnostics reject scenes larger than 4096 points. Loading the synthetic scene restores the identity camera; its diagnostic assertions assume this camera and positive multiplier. The maintained verification skill is `.agents/skills/verify-splatforge/`.

The compute shader unpacks f16 Gaussian/SH storage; normalizes (w,x,y,z) rotation; applies exponentiated scales and multiplier; constructs R*S*S^T*R^T; projects with the perspective Jacobian into framebuffer pixels; adds a 0.3-pixel covariance floor; computes inverse conic and three-sigma maximum-eigenvalue radius; rejects near/far and off-screen bounds; evaluates view-dependent SH through degree three; compacts survivors and writes complemented positive float depth keys. The inherited four-pass GPU radix sorter supplies far-to-near indices. GPU indirect draw uses the compacted count; six-vertex quads reconstruct screen bounds and emit premultiplied exponentially decaying alpha, composited far to near without depth writes.

The owned binary fixture `public/fixtures/synthetic.ply` contains six Gaussians: two anisotropic/rotated lobes, an overlapping blue background/red foreground pair, a behind-camera point, and a far off-screen point. Identity-camera expected survivors are 0–3, ordered 2, then 0/1 in either tie order, then 3. A small first-order SH coefficient exercises view dependence. The fixture generator is `src/utils/synthetic.ts`.

PLY import accepts only binary little endian scalar float/uchar layouts, validates the header, stride, data length, required properties, SH degree, finite half-representable attributes, nonzero quaternions and supported log-scale range before GPU allocation. Limits are 256 MiB input and one million points, further constrained by adapter storage limits. This is bounded admission, not streaming/chunk loading. Replacement destroys old scene/sorter buffers. Unsupported layouts fail visibly while retaining the previous scene.

Validation status is recorded in the external implementation report. CPU tests and build do not establish GPU shader validity, rendered quality, performance or extra-credit tile sorting/f16 arithmetic. No performance comparison or photorealistic-scene claim is made.
